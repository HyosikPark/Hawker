# GEO/AEO 시장 조사 — "에이전트 발견 최적화"를 제품으로? (2026-08-31)

## 결론: 신규 진입 하지 말 것. 대신 Hawker의 기능으로 흡수.

## 두 플레이버 구분 (핵심)
- **(a) 인용·언급되기** (ChatGPT/Perplexity가 브랜드 언급) = 오늘의 GEO 시장. 돈이 여기 있음.
- **(b) 발견·호출되기** (에이전트가 내 API를 골라 실행·결제) = 인프라는 있으나 구매자 부재.

## (a) GEO 시장은 실재하고 크지만 — 솔로에겐 늦음
- 18개월간 $300M+ 투자. Profound $1B 유니콘($96M 시리즈C). Scrunch $225M 인수(=통합 국면).
- **그런데 만들기 쉬운 계층(모니터링)이 정확히 커모디티화됨**: 40+ 툴, $29/월, Semrush/Ahrefs 번들 무료화.
- **측정의 함정**: AI 엔진이 비결정적 → 같은 날 툴마다 점수 다름. "인용 8→11%"가 노이즈와 구별 불가. 임원 74%가 측정 불신으로 이니셔티브 축소. Forbes: "AI 가시성 수치는 못 믿는다."
- → 범용 GEO 모니터링 솔로 진입 = 타이밍 늦음 + 커모디티 + 인큐번트 + 측정불신 3중고.

## (b) 에이전트 발견 최적화 = 진짜 웨지지만 12~24개월 이름
- 인프라는 실재(MCP 레지스트리, x402 Bazaar, .well-known).
- **그러나 구매자 부재**: 에이전트 실사용 누적 $50M·건당 $0.30 → 판매자가 "발견 안 됨" 통증을 아직 안 느낌. (a)에 돈 흐른 건 통증이 현재진행형이라. (b)는 미래시제.
- **llms.txt의 교훈**: 매니페스트 최적화 도구는 엔진이 그 신호를 실제로 쓸 때만 가치 생김. llms.txt는 AI봇이 0.1%만 읽음 → "표준파일 최적화해드립니다"류 제품의 위험 경고.
- **아무도 "셀러에게 파는 발견 최적화 SaaS"를 확립 못 함** = 공백이자 아직 이른 공백.

## 결정적 반전: Hawker가 이미 (b)의 정답 쪽에 서 있다
- (b)의 방어 가능한 자리 = "최적화 레이어를 셀러에게 파는 것"이 아니라 **"에이전트가 즉시 발견·결제·사용할 공급(상품화된 API)을 만드는 것"**.
- 발견은 결국 "팔릴 준비된 좋은 상품"이 있어야 성립. → **Hawker 방향이 이미 정답.**
- "발견 최적화 툴"은 별도 제품으론 이르지만, **Hawker 상품에 딸린 기능**("멀티 서피스 자동 등록 + 에이전트 친화 메타데이터")으로는 지금 붙일 만함.

## 최종 권고
1. 범용 GEO 모니터링 신규 진입 ❌ (늦음)
2. 독립형 에이전트 발견 최적화 SaaS ❌ (구매자 12~24개월 뒤)
3. **Hawker 기능으로 "멀티 서피스 자동 등록 + 메타데이터 최적화" 흡수** ✅ (b의 유일한 현재형)
4. 측정은 "클릭/전환"(불신) 대신 **"에이전트 호출 수·결제 성공 건수"**(결정적·검증가능)로 — x402 결제 데이터 쥔 공급 플랫폼만의 구조적 이점.

## 종합 (a·b 두 리서치 합쳐서)
효식님의 "(b)를 제품으로?" 직감은 방향이 맞지만 타이밍이 이름. 그리고 우리가 하려던 Hawker가
이미 (b)의 정답 위치. 즉 **전환할 필요 없이, Hawker에 발견 최적화를 기능으로 흡수**하는 게 답.
발견 플레이북(docs/agent-discovery-playbook.md)이 그 실행 체크리스트.
